# UI 与编辑工作流优化分析（2026-10-17）

## 1. 基线与结论

代码基线：`6.0 / fc79d4bcbe4ee124e374984a353549d31e585a2f`。真实资源基准：`/home/j60100428/game/wc4/World Conqueror 4_1.30.0`。

本轮检查首页、窗口壳、将领、技能、兵种、国家、总部科技、资源浏览器、布局和数据检查窗口；对照已有 Windows 实测及修复矩阵，读取实际 JSON、布局和游戏分析资料，并查看此前生成的将领/科技 PNG。**这是分析节点，未修改运行代码；下文建议均不表示已经实现。**

当前可以继续复用的基础包括目录/APK 加载、增量输出、技能/特性解释、将领/进修/技能升级静态预览和总部科技网格。下一轮最有价值的方向是：

没有在 Linux 上运行本轮 Windows WPF 交互，也未运行 Android 游戏。本轮不重新引用历史的 176 项通过作为新 UI 验收结果；测试与发布的既有结论继续见 [2026-10-14 修复矩阵](2026-10-14-windows-review-fixes.md)。

## 5. 将领、技能与兵种页面的具体设计

### 5.1 将领编辑

建议保留现有深灰界面，先统一控件和信息层级；项目游戏预览继续使用来源美术。页面组织如下：

```text
项目名 / 将领 / 当前记录       [草稿状态] [保存] [更多]
列表与筛选       | 常用属性 / 技能 / 进修 / 高级 | 游戏预览
头像、名称、Id   | 当前标签的字段与解释         | 详情/进修/升级
类型、已修改     | 输入错误贴近对应字段         | 当前/来源对照
```

窄窗口折叠列表，属性与预览使用标签；分栏比例和最后选中记录保存在用户设置，不写游戏目录。固定“保存”和“返回项目”，随机/低中高模板归入“模板”菜单；删除放入“更多”并保留确认。

常用属性首屏展示名称、品质、军衔、六项能力。头像细调和只读原始 JSON 放进“高级/资源”区，避免占据首屏。字段保留 `MilitaryRank` 等原名作为次级信息，对已确认枚举提供中文候选；未知值原样显示与保存，不用第一项悄悄替换。

将领选择至少提供“全部 / Type=1 / Type=3 / 其他”，结合确认过的语义显示业务名称，并增加“仅已修改”。列表保留头像缩略图、名称和 Id；缺半身像不作为错误，本来只有头像的角色继续使用其自身头像。

### 5.2 技能槽与技能等级链

槽位卡片显示“图标 + 中文名称 + 实际 Level + Id”，点击“替换”打开可搜索面板。搜索结果先按 Type 聚合，再选择该 Type 的等级，完整说明继续复用现有 `ProjectDataDescriptions`，而不复制另一套描述解析。

拖动调整技能顺序，清空槽位时显式处理 Id=0；高级模式仍允许输入 Id 列表。操作预先检查缺失引用、重复含义、SkillsMax 和当前布局槽位，保留来源已有异常并明确说明，不自动修正未编辑的数据。

技能页可用“Type → Level 链”的树或分组列表：原始数据是 178 类而非 901 个互不相关技能。右侧维持当前/下一等级预览，增加整链效果和费用对照。“追加下一级”前显示将新增的 Id 和将修改的 UpgradeId；钢铁洪流 Lv5→Lv6 继续按现有能力实现，**新等级不等于新增第六个技能槽**。

从将领跳到技能、特性或布局编辑时，应支持返回到原记录和原滚动位置。进一步让相关文档保持草稿需要共享文档状态，不能只把场景对象放进导航栈：当前 [SetCurrentScene](../../Views/MainWindow.xaml.cs#L499) 会确认并释放旧场景，当前 [IUnsavedScene](../../Views/IUnsavedScene.cs) 只是保存/放弃接口，并非完整文档管理器。

### 5.3 兵种特性与说明

Feature/FeatureLevel 改为成对行：

| 槽位 | 特性 | 等级 | 解释 | 操作 |
|---|---|---|---|---|
| 1 | 中文名称与 Type | 项目已定义等级列表 | 当前参数和介绍 | 替换、清空、定位配置 |
| 2 | 中文名称与 Type | “未显式配置”或具体 Level | 未显式配置时明确标记参考 | 上移、下移 |

空 FeatureLevel 在原始兵种中确实存在；如果只是查看或重排，不能为凑齐数组擅自补造 Level。用户明确设置级别后才记录相应修改，并在保存前预览实际序列化结果。数组数量不一致时显示具体多余/缺失槽，避免只显示一个笼统警告。

兵种页的战斗、生产成本、编队、动画位置分组折叠；“基础配置值”和模拟后的编队/等级值并列标明来源。国家列表同样用中文候选辅助编辑，Id 保留在次级标签。

## 6. 新 UI 预览的可行性

### 6.1 兵种详情：有能力实现，建议优先新增

指定 1.30.0 的 [layout_x.xml](</home/j60100428/game/wc4/World Conqueror 4_1.30.0/assets/layout_x.xml>) 已有：

| 表单或模板 | 可绑定内容 | 边界 |
|---|---|---|
| `form_unitinfo` | 名称、攻击/防御/移动/射程/HP、六个特性按钮、所选将领区域 | 战斗实际值依赖将领、科技、状态等，基础预览不能当实战值 |
| `tpl_army_stat` | 通用单位能力区 | 可与已有编队/等级模拟结果联动，但需标注计算范围 |
| `form_eliteinfo` | 精英名称、等级、特性、详情区域 | 需关联 EliteArmySettings 与具体 ArmySettings 记录 |
| `form_upgradeelite` | 当前/目标级别、属性和特性对照 | 费用、材料和升级关系需要独立读取，不能按 Id 尾数猜等级 |

第一阶段使用已验证的静态兵种图标或可靠动画帧，绑定草稿中的基础数值、特性说明和布局。图集名、锚点和偏移来自指定项目；不能找到对应美术时显示原因，不使用其他兵种替代。

`MotionalArmy` 是原布局中的特殊节点，当前 [GameUiLayoutRenderer](../../WC4MapEditor.Rendering/Imaging/GameUiLayoutRenderer.cs) 主要绘制图片/文本，没有对应动画实现。完整动作、方向、编队和游戏运行状态应放在第二阶段，需确认 `Anim → def_motion → 动画/图集` 的链路。

现有预览的点击区域 [GameUiHitRegion](../../WC4MapEditor.Rendering/Imaging/GameUiLayoutRenderer.cs#L10) 只持有 SkillId；扩展兵种后宜改成带业务类型与引用的区域，分别处理技能、特性、精英和布局控件。

### 6.2 国家：先做带征服上下文的静态预览

`form_conquestcountry` 约 600×264，具有国旗、名称、阵营图标、星级和数量区域。可以把国家页改为“基础国家 / 当前征服实例 / 游戏预览”，选实例后绑定真实星级和阵营。

存档中的将领数量、外交状态和原生运行状态不能仅凭 CountrySettings 得出；未取得对应上下文的字段显示为未提供。`form_countrytech` 与总部 `form_technique` 使用不同的数据关系和布局，不能直接套总部科技树的节点算法。

### 6.3 现有将领预览：增加定位和对照

已查看此前的古德里安 PNG，当前半身像、六项能力和技能槽已经能组成可辨认的详情画面；应进一步提供以下编辑便利：

- 当前草稿与来源基线切换，或并排/滑动对比；在文字/技能变化处标出差异。
- 点击能力、姓名、军衔或头像后定位属性，形成预览与编辑双向选择。
- 字体、布局和语言放进“预览设置”，主工具栏保留模式、缩放、更新和导出。
- 缺资源、断链和溢出分级聚合；点诊断可高亮控件和定位布局。
- 输入无效时持续显示“展示上次有效草稿”，并保留现有导出阻止逻辑。

现在 `PHONE/HD`、`PAD/HD`、`PAD/SD` 主要是字体配置选择，图片仍使用 HD；若要称为设备效果，需要补建视口、比例、安全区和相应资源选择，不能只改下拉标签。

## 7. 科技树、地图与资源浏览器

### 7.1 总部科技

此前 PNG 已能表达同格双节点和依赖，但全网格缩到小面板后，文字、Id 与细箭头不易阅读。当前 [JsonTableEditScene](../../Views/JsonTableEditScene.cs#L90) 的科技页采用上下各半区域，预览高度还会被工具栏、说明和诊断占用。

建议宽窗口并排或允许预览独立放大；窄窗口用标签页。增加适应区域、100%、选中节点居中和拖动平移；Categorys 的数字保留，旁边显示经项目确认的中文类别。边按“依赖/升级”分别开关，突出所选节点的直接前后关系。

如果增加拖动节点，先显示网格落点、跨组行为和冲突预检，确认后一次更新 Position 并可撤销。46 个合法双节点格不能一概判冲突；移动后要区分两个不同 Type 的合法组合与同 Type/超容量重叠。

当前 [点击计算](../../Views/Assist/HeadquartersTechPreview.cs#L63) 会将整格空白处的点击夹到某个成员；改为复用渲染产出的实际卡片区域，空白点击不改变选择，可减少误选。

### 7.2 地图工具

现有地图并非没有模式和提示：已有地形/部队等编辑模式、笔刷设置、帮助叠层、对象弹窗与撤销。改进重点是把常用能力变成可见且可点的界面。

建议左侧工具切换，画布保留中间，右侧显示当前格/选中对象，底部保留坐标、模式、笔刷和保存状态。常用的地形、建筑、部队、省区/归属提供可搜索缩略图和参数；快捷键作为按钮提示，继续调用现有命令和快照，避免新增一套绕过撤销的操作路径。

“删除全部”“覆盖区域”“自动海岸”等批量操作展示影响范围与撤销说明。选中对象列表支持双击定位，区分地图窗口坐标与原始世界索引。底部 [水平工具栏](../../Views/RenderSceneBase.cs#L267) 在窄窗口应折叠到菜单，避免遮挡场景名称和窗口按钮。

### 7.3 资源与输出变更

资源浏览器已有扩展名/类别/相对路径搜索；建议加状态筛选：原始资源、输出覆盖、输出新增、内存草稿和外部冲突。缩略图只加载可见项，并设容量上限；PKM、图集 XML/图片成组展示，避免用户误以为它们是互不相关的文件。

新建“变更清单”页显示每条路径的来源、输出、状态与字段摘要。保存前展示将写出的文件；选择“恢复原始”前说明将删除哪份覆盖文件，操作确认后仍走已有增量保存规则。

三类状态必须分开：内存未保存不等于输出文件；有输出文件不必然表示相对来源有内容差异；外部修改应通过已有版本检查处理。只有确需判断内容时才做字节/哈希比较，不在每次输入时遍历全部游戏文件。

## 8. 响应速度与界面一致性

### 8.1 已修过扫描，仍有进一步优化点

2026-10-14 已修首次重复扫描和后台加载，不能把该旧问题当成仍未修复。当前另外存在两条可优化路径：

- 首页和打开入口都会构建 [ProjectEditorCatalog](../../WC4MapEditor.Core/Assets/ProjectEditorCatalog.cs#L21)，构造时同步解析 25 张 JSON；指定项目合计读取 2,472,825 字节。这里是调用链与文件规模确认，**未测得本轮 Windows 卡顿时长**。建议按资源 Revision 缓存可用性/数量，仅对受影响表重算，并在后台做非必要校验。
- 将领/技能/资源列表在输入搜索时清空重建；ReferenceDetailsPanel 也随属性更新重建卡片；预览 180ms 延迟后仍在 UI Dispatcher 上同步渲染。建议稳定集合视图、适度防抖、复用卡片、图区/文字分级失效；先测量，再决定是否将只读快照渲染移到后台。

后台预览必须取消或忽略过时请求，且不能跨线程使用 WPF 控件或在渲染时释放仍在用的 SKBitmap；不能只增加 Task.Run 就认定已优化。

### 8.2 共用样式与文案

保留当前桌面视觉方向，统一颜色、间距、字体等级、焦点框、选择态和错误态。按钮中的 Emoji 在不同 Windows 字体上外观不稳定，适合换为固定矢量图标加中文标签；项目游戏图片仍从用户指定资源读取。

功能名称用业务名称，代码字段保留作辅助。枚举、布尔与外键采用合适控件；不明确的枚举保留原值。搜索框用真实水印，避免把“搜索...”写进 Text 再用 StartsWith 判断；增加清除按钮、结果数和无结果提示。

界面显示语言与文本保存目标独立。当前技能解析器固定写 `stringtable_tw.ini`，说明卡默认 cn；应明确显示“正在修改哪种语言”，后续增加 cn/tw/en 对照与独立保存目标，不把切预览语言误当成翻译或同步保存。

配置撤销应单独建记录级/字段级历史，覆盖克隆、删除、重排和模板应用；TextBox 内的 Ctrl+Z 不能代替整个文档的撤销。统一 Ctrl+S 等命令时保留文本编辑焦点行为，不把地图键盘处理套到所有页面。

## 9. 实施顺序与验收

| 批次 | 建议范围 | 核心验收 |
|---|---|---|
| 第一批 | U01–U05、统一保存状态、将领工具栏/分类/属性重排、搜索水印与导航位置记忆 | 所有页面可关闭/还原窗口；普通 Tab 不被吞；国家属性全可达；负坐标副屏缩放正确；小窗与高 DPI 可操作；导航不带入其他项目状态 |
| 第二批 | 技能槽选择、成对特性、变更清单、语言保存目标、诊断定位 | 改某槽只改预期数组；空 FeatureLevel 不被补造；非法输入不部分应用；查看不产生输出；保存、恢复、外部冲突结果可核对 |
| 第三批 | 兵种/精英/国家静态预览、将领来源对比、科技树交互 | 预览读取当前草稿和指定布局；点预览定位正确；更新/切项目不显示旧图；PNG 与所选模式一致；动作和实战边界明确 |
| 后续 | 地图停靠面板、配置文档历史、完整动画 | 命令入口和撤销一致；历史内存受控；动画引用、方向和缓存生命周期有实测证据 |

建议的 Windows 验收组合：

- 1250×700 默认窗口、760×520 最小窗口、最大化；再测试 125%/150%/200% DPI 和不同缩放的双屏移动。
- 将领列表 → 搜索 → 技能 → 返回原将领；保留选中和滚动，保存/放弃/取消各执行一遍。
- 钢铁洪流 Lv5 → 追加 Lv6 → 给将领替换该技能 → 对比来源 → 保存 → 重开，核对只输出预期配置。
- 基础兵种 FeatureLevel 为空 → 仅查看 → 退出；输出无变化。显式选等级、调换槽位、非法输入再修复，各核对数组与说明。
- 总部双科技格选择、点击空白、缩放、切类别、节点移动取消与确认；确认时能一次撤销且没有覆盖合法双节点。
- 国家详情最后一项、长名称、长错误提示、不同征服实例，核对滚动、旗帜与星级上下文。
- 编辑草稿 → 资源刷新 → 变更清单 → 保存同表冲突，确认双方内容仍在，失败不伪装成功。
