# 项目优先：从首页加载到项目内编辑

节点日期：2026-10-11。此节点根据 Windows 使用反馈调整桌面入口，在[增量输出规则](incremental-output.md)上继续开发。原来的完整副本、增量保存和审计节点均保留；当前桌面操作以本页为准。

## 1. 首页与项目概览

启动后首页显示项目加载表单，来源目录必填。首页不显示战役、征服、将领、国家等编辑入口；程序也不自动扫描随包的 `Resource/WC4DATA/assets` 作为游戏数据。

| 字段或操作 | 当前行为 |
|---|---|
| 游戏项目来源目录 | 输入本机实际路径或点击“选择来源”；支持解包项目、直接的 `assets`，以及包含 `WC4DATA/assets` 或 `Resource/WC4DATA/assets` 的目录 |
| 修改输出目录 | 可以输入或选择；可以填写尚未创建的目录；留空时自动采用默认值 |
| 默认输出 | 在来源目录的同级建立 `<来源目录名>-edited`；更换来源时，只自动更新仍使用默认值的输出 |
| 加载项目 | 校验来源、输出及项目描述；新目录生成 v2 增量项目，随后加载来源与输出合并的资源 |
| 选择已有输出 | 从 `.wc4-project.json` 填入来源和输出，再点击“加载项目”；来源字段仍需有效 |
| 已有匹配输出 | 同一来源的输出项目直接继续，保留已有修改；不重新创建或清空 |
| 已有不匹配输出 | 拒绝加载，提示此输出属于另一个来源项目 |
| 非空且无项目描述的输出 | 拒绝创建，不覆盖其中的文件；请选择新的、空的或已创建的项目输出目录 |
| 来源与输出重叠、链接或非法路径 | 拒绝加载或保存；输出不能位于来源中，来源也不能位于输出中 |

路径示例：

```text
来源：/home/j60100428/game/wc4/World Conqueror 4_1.30.0
默认输出：/home/j60100428/game/wc4/World Conqueror 4_1.30.0-edited
```

在 Windows 上填写自己的实际目录，例如 `D:\Games\World Conqueror 4_1.30.0`，默认输出就是 `D:\Games\World Conqueror 4_1.30.0-edited`。程序没有写死 Linux 示例路径。

加载成功后显示项目概览，列出来源、输出、当前资源数，以及分组的编辑入口。概览和资源管理器读取同一份项目索引；地图入口打开项目中的资源列表，用户从列表选择文件。新增地图操作也放在项目内。

新增 BTL 默认保存在输出的 `assets/stage`，新增 world 默认在输出资源根。新增征服固定引用当前项目的 `world.bin`，地图编号为 1，保留上下各两行边距；缺少这份有效底图时禁用新增征服。新关卡仍需同步相应 JSON 节点和游戏文件命名，创建 BTL 不会自动接入游戏菜单。

返回编辑器首页会回到当前项目概览。切换项目进入加载表单，成功后替换当前项目；返回当前项目或取消操作保留已有会话。关闭项目清理地图场景及数据/图片缓存，回到加载表单。离开、关闭或切换时沿用保存、放弃、取消的未保存确认。

主窗口以 1250×700 的普通窗口居中启动。首页、地图及各数据编辑页共享顶部窗口控制：点击右上角最大化按钮、双击标题栏，或按 F11，可将当前编辑页展开至屏幕工作区；再次操作还原窗口。最大化后切换编辑项会继续保持最大化，标题栏占独立一行，不遮挡编辑工具栏。

## 2. 编辑入口与实际数据

概览按有效文件和配置表显示数量。配置要求可解析的对象数组，专用编辑器缺少必需表时禁用并提供悬停说明；空对象数组仍可进入编辑器新增记录。一个模块缺少资源不阻止整个项目加载，用户可以从“全部资源”补充或修复。

| 项目内入口 | 数据来源与配套资源 |
|---|---|
| 战役关卡 | `assets/stage/stage*.btl`；`StageSettings/ScenarioSettings` 提供游戏内节点、奖励等配置，配置可从资源管理器打开 |
| 征服关卡 | `assets/stage/conquest*.btl`；地图 ID=1 的地形来自同项目 `world.bin`，国家配置来自 `ConquerSettings/ConquerCountrySettings` |
| 活动、前线与其他关卡 | `stage` 中的 event、frontier、generalstage、legend、warzone、invadecorps 等 BTL |
| 世界地形地图 | 由 YSAE 文件头识别的 world BIN/DAT；辅助 `map1.bin/map1_hd.bin` 不当作完整地形地图 |
| 将领编辑 | `json/GeneralSettings.json`；技能引用 `SkillSettings`，半身像 `image/generalphoto`、头像 `image/heads`，位置 `config/def_portraitpos.xml` |
| 国家与征服国家 | `json/CountrySettings.json`、`ConquerCountrySettings.json`、`ConquerSettings.json`；战术图集和 `image/image_flags_hd` 提供图像 |
| 技能、兵种、军队状态 | `SkillSettings`、`ArmySettings`、`ArmyBuffSettings`；兵种编辑还要求 `config/def_armypos.xml`，本地化使用项目字符串表 |
| 建筑与设施 | `BuildingSettings.json`、`FacilitySettings.json` |
| 国家科技 | `CountryTechSettings.json`；更正旧入口“局内科技”的含混名称，不表示该页面编辑 `TechnologySettings.json` |
| 集团军与援军 | `ArmyGroupSettings`、`ArmyGroupReinforcementSettings`、`EventSettings`、`EventStageSettings`、`EventCalendarSettings` |
| 集团军事件、事件效果、征服事件 | `ArmyGroupEventSettings`、`EventBuffSettings`、`ConquerEventSettings` |
| 布局编辑 | `assets` 根部 `layout*.xml`，字体和图集来自同项目 |
| 全部资源 | 同项目其余 JSON、XML、INI、图片、地图及其他资源；支持格式进入对应编辑页 |

切换项目重新创建专用解析器，清理本地化、地形定义、图集、字体及地图场景缓存。文件缺失时不拿上一项目或内置目录的表补齐；旧解析器的保存校验仍会拒绝写入旧资源根。地形类型及变体数量也以当前项目的 `def_mapterrain.xml` 为准，读取 UTF-8 或 GBK/GB18030 中文名称。

JSON 编辑保持原来的完整表保存规则：改一行或加一行，输出整张变更表；其他未改表不输出。新增将领可能同时输出位置 XML、字符串表和用户制作的图片，取决于实际操作。JSON 记录新增不会自动完成全部游戏引用、制作头像或生成新机制，配套关系仍需用户编辑并检查。

## 3. 实际 1.30.0 关系核对

实现前只读检查了 `/home/j60100428/game` 下的项目分析、JSON 参考、扩展教程、地图格式分析与整合包修改报告。外部报告主要针对 1.28.0，路径和记录数以这次选定的 1.30.0 实际文件为准。

| 核对项 | 本机 1.30.0 结果 |
|---|---:|
| 全项目 / assets 文件数 | 4,580 / 3,474 |
| `assets/json` 表 / 记录 | 81 / 22,055 |
| BTL 总数 | 1,383 |
| BTL 文件族 | 战役 295、征服 9、活动 731、前线 213、传记 40、传奇 60、战区 25、入侵 10 |
| 将领 / 技能 / 兵种 | 1,189 / 901 / 736 |
| 国家 / 征服国家 / 征服设置 | 60 / 356 / 10 |
| 将领进修 / 称号 / 传记节点 | 43 / 8 / 40 |
| world 地形 | YSAE/v4，148 × 54，143,872 字节 |

40 个传记节点对应的 `generalstage_<Id>.btl` 全部存在。将领技能引用除占位 `0` 外均能在技能表找到；将领的 `Photo` 与 `EName` 不能混同，多个剧情记录可以共享头像。九个征服 BTL 仍应结合 `ConquerSettings` 的可见、普通/挑战关联理解，不能仅根据表行数假定有十张 BTL。

这些关系用于资源定位和编辑入口组织，不表示已经确认 Android 所有机制或完成完整游戏美术渲染。PKM/ETC、完整对象/海岸图像及 world/BTL 联动编辑边界继续见[前一审计节点](../../audits/2026-10-11-incremental-project.md)。

## 4. 验证与 Windows 验收

回归覆盖来源必填、默认同级输出、自定义新目录、匹配输出继续、不匹配来源拒绝、非空输出保护、关闭项目、失败切换恢复，以及跨项目将领/国家/技能/兵种/本地化数据隔离。

完整回归结果：**109 项通过、0 项失败**；Windows `win-x64` WPF 交叉构建成功，**0 错误、9 条既有警告**。本机日志为 `tmp/project-first-full-tests.log`、`tmp/project-first-build.log`，这些临时日志不入库。

真实 1.30.0 用临时输出验证：所有概览入口能识别项目资源；修改一个将领、新增一个将领和国家，重开后数据存在；输出只有项目描述、`GeneralSettings.json`、`CountrySettings.json` 和 `def_portraitpos.xml` 四个文件。原始 4,580 文件的 SHA-256 在验证前后核对。

Windows 仍需实际运行验证以下交互：

1. 首次启动仅显示加载表单；来源留空显示错误，Tab 可在路径框和按钮之间移动。
2. 选择或输入游戏目录，默认输出自动变为同级 `-edited`；自定义输出不被后续来源输入强制覆盖。
3. 加载后显示项目概览，地图列表来自项目；将领、国家等列表数量和内容匹配所选版本。
4. 编辑/新增并保存，输出只出现必要文件；返回、切换、关闭时的保存/放弃/取消均生效。
5. 再次加载同一来源和输出继续编辑；选其他来源配同一输出时拒绝，已有修改保留。
6. 缺少一张专用配置表的测试项目显示禁用原因，不显示另一项目的数据；中文路径、空格和较小窗口可正常使用。

Linux 上的 `win-x64` 交叉构建和非 WPF 回归不能代替以上 Windows 窗口操作验收。此节点没有 APK 打包、签名或安装流程。
