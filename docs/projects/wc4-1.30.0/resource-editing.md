# 1.30.0 图片加载与配置表编辑

更新日期：2026-10-11。此节点延续 [项目优先工作流](project-workflow.md) 和 [增量输出](incremental-output.md)。先加载来源目录，所有详细入口在项目内出现；输出默认在来源同级 `<项目名>-edited`。

## 1. 图片为何可能没有显示

编辑器需要正确匹配文件路径、图集矩形和实际编码。`Texture.name="tacticalmap.png"` 并不要求目录一定有 PNG；真实 1.30.0 的对应图片是 WebP。国家旗帜通常是 `image/image_flags_hd.xml` 中的 `flag_<国家Id>.png` 图块，不是一张同名独立 PNG。

本轮已修复相对路径/子目录、布局 `image/` 前缀、像素格式和透明度转换以及保存后缓存问题。PNG/WebP 使用随编辑器部署的 Skia 解码，不要求系统另外安装 WebP 编解码器。

| 图片 | 项目内位置 | 读取规则 |
|---|---|---|
| 将领半身像 | `assets/image/generalphoto/general_<键>.webp/png` | Photo 优先，空时 EName；WebP 优先 |
| 圆形头像 | `assets/image/heads/general_circle_<键>.webp/png` | 与半身像分开读取，不按将领 Id 猜名称 |
| 战术头像 | `assets/tacticalmap.xml` 中 `head_<键>.png` | XML 裁切实际 tacticalmap 图片 |
| 国家 HD 旗帜 | `assets/image/image_flags_hd.xml/webp` | `flag_<CountrySettings.Id>.png`；Logo 不替代 Id |
| 国家战术旗帜 | `assets/tacticalmap.xml/webp` | 大旗 `flag_<Id>.png`，小旗 `f_<Id:D2>.png` |
| 科技图标 | `assets/image/image_countrytech_hd.xml/png` | `countrytech_<Type>.png`；也支持对应 WebP 图片 |
| 布局引用 | 整个 assets 的图集及散图 | 包含 image 子目录，保留相对路径，同名普通/HD 条目优先 HD |

实际 1,189 条将领数据中有 **262 条记录、80 个不同头像键没有半身像**，例如 Christian、Leopold、Gamelin。它们已有圆形/战术头像，不表示编辑器能生成缺少的半身像。除 `Id=0` 的空记录外，其余将领记录都有这两种头像。界面现在区分“未提供此图片”和“加载失败”，失败原因与命中路径可从提示查看。

60 个国家都具备 HD 与战术大旗帜，因此现有国家图片空白应继续检查实际错误提示和发布文件。新国家需要另外导入/制作旗帜，新增 JSON 记录不会自动增加图片。

## 2. PKM 图片预览

从“全部资源”打开 `.pkm`，进入只读图片页；显示名称、实际尺寸及 ETC1 RGB 格式。可滚动查看原尺寸图片，返回项目概览。

当前 417 文件全部能解码。包括 `assets/map/map1_1@2x.pkm`、`map1_a1@2x.pkm`、`assets/image/map/01.pkm` 与海岸等纹理页。`map1_a` 等遮罩资源单独显示；预览不自动与颜色纹理组合，也不代表地图渲染已完成对应游戏美术效果。

本轮没有 PKM 编码器，页面不提供保存。不要把 PNG 字节存为 `.pkm`；一般 PNG/WebP 的图集编辑仍使用已有图集编辑器。

## 3. 新配置入口

加载项目后，在“扩展配置与界面资源”中可选择：

- **将领进修、称号与传记**：进入三张表的列表，再双击打开。43 条进修、8 条称号、40 条传记关卡。
- **总部科技**：直接打开 `TechnologySettings.json`，当前 191 条。原“国家科技”页面仍编辑 `CountryTechSettings.json`，两表用途不同。
- **全部配置表**：浏览 `assets/json`，当前 81 张对象数组表、22,055 条记录。双击任何一张打开字段编辑器。

assets 根目录另外三个对象型 JSON 仍用文本编辑器。地图、图集 XML 与本地化继续使用各自入口。

## 4. 按记录和字段操作

1. 左栏搜索 Id、名称或字段值，选择记录；右侧按原字段顺序展示数据和类型。
2. 字符串直接填文字；数值、布尔、数组、对象按类型输入。数组/对象输入 JSON，如 `[1191,1341,1071]`；`null` 用独立勾选框切换。
3. “应用当前记录”只将校验通过的字段写入内存；切换记录和保存也会应用。任何字段无效时整组本次输入不部分应用。
4. “新增记录”从现有字段构造默认值；“克隆记录”保留当前记录所有字段和嵌套值，并给数值 Id 分配当前表最大值加一。空表可新增第一条记录，再“添加字段”。
5. “删除记录”仅删除选中行，不自动清除其他表引用；“添加字段”初始为 null，无可推断类型时输入 JSON 值。
6. “保存表”只写当前变化表，保持相对结构。未修改表不输出；恢复来源值并保存会移除对应覆盖文件。
7. “重载”读取最新有效文件；若有未保存修改，先确认放弃。离开、关闭与切项目遵循保存/放弃/取消流程。

字段名称、大小写、未知对象、缺失字段、原 null、数组以及 UTF-8 BOM 保留。已有重复 Id 的行各自编辑，不强行合并；保存拒绝新增加的重号。SHA 冲突检测防止覆盖其他页面/外部程序已修改的文件。

修改后的 JSON 用标准缩进输出，注释和原有排版不作为保真对象。未改字段的值类型和内容保真；整数、布尔/数组元素会检查，外键和引擎范围仍需实际关系检查。通用表保存后清理专用解析器实例，重新进入专用页面可看到新值。

2026-10-14追加更正：通用表保存只使相关表的干净解析器失效，其他解析器和字符串草稿保留；同表仍有草稿时保留实例，保存由内容版本检测拒绝冲突。具体操作见第10节，前述刷新描述保留为旧节点行为。

## 7. 2026-10-12 操作规则补充

此节根据旧版 Windows 复现追加，前六节保留当时节点的资料与测试统计。逐项结果与验收见 [Windows 复现复核矩阵](../../audits/2026-10-12-windows-regressions.md)。

| 操作 | 当前规则 |
|---|---|
| 资源浏览器“刷新” | 只重新扫描文件列表并清图片缓存，不清配置解析器、地图文档或撤销历史。外部修改配置后，需要在对应编辑器明确重载 |
| 离开、关闭、切项目 | 有草稿时继续显示保存/放弃/取消；选放弃才清草稿，保存失败保留页面和修改 |
| 外部修改后保存 JSON | 检查有效来源/输出文件的内容版本；变化时拒绝保存并提示重新加载，当前草稿与外部文件都保留。重载后再应用需要保留的编辑，不自动合并整张表 |
| 导入同名图块 | 更新像素与尺寸，保留原 X/Y、RefX/RefY 和未知 XML 属性；新增名称才创建新对象 |
| 复制与粘贴 | 复制时保存当前独立像素和对象属性，粘贴分配唯一名称与独立像素；后续替换或删除源图块不会改变剪贴板内容 |
| 图块属性 | 通过草稿确认并拒绝重名，改名同时更新名称索引与像素键；负锚点合法，锚点不以图块宽高为界 |
| 删除所有图块 | 图集仍是图集，保存空 XML 和透明画布；重开不自动恢复整张源图 |
| 制作国旗 | 战术与 HD 的图片/XML 先全部准备，半组缺失、XML 错误或暂存失败就中止；常规保存失败不发布半组结果 |
| 保存后看地图图片 | 相关缓存根据资源 Revision 重读，新增原缺图也可恢复；外部图片变化可用文件列表刷新触发扫描，不必关闭项目 |
| 新建征服 | 使用当前项目的有效 world.bin，编号固定 1、上下各留两行；源高度不足时提前拒绝，不允许新建无法在当前项目模式重开的编号 2 |

批量文件保存仍有断电与跨进程竞争边界，具体见矩阵。“导出完整画布 PNG”的对话框标注为“源图原样”，保留该导出语义；核对当前排布、导入和粘贴结果应保存图集后重开查看。源项目未提供的半身像保持原状。

本节追加用户Windows实测后的操作变化。原报告及修复前统计保留；逐项处理、19项定向/176项完整回归与Windows验收见 [修复矩阵](../../audits/2026-10-14-windows-review-fixes.md)。

### 10.1 将领技能说明

加载指定游戏目录/APK → 项目内“将领编辑” → 选择将领。在 `Skills` 的Id输入框下，按数组顺序显示每个槽位的技能名称、实际Level、Id、介绍、效果/触发率和下一等级。修改Skills列表后立即更新；点击“编辑此技能”进入技能页并定位Id，离页继续检查保存/放弃/取消。

| 内容 | 解析规则 |
|---|---|
| 将领Skills | 引用SkillSettings的Id，等级直接读取该记录Level，不按Id末位猜测 |
| 名称/介绍 | 按SkillSettings.Type查 `skill_name_<Type>` / `skill_info_<Type>` |
| 简体中文（默认）/英语 | 读取当前项目stringtable_cn.ini / stringtable_en.ini |
| 繁体中文 | 读取技能解析器的stringtable_tw.ini文本草稿；与技能文字编辑的保存位置一致 |
| 介绍中的参数 | 已确认的单参数规则读取SkillEffect或ActivatesChance，未知多参数保留占位符并提示 |
| Id0或缺失Id | 空槽明确显示；缺失记录说明缺失，不显示另一技能的资料 |

钢铁洪流是Type24，原链尾1245/Lv5；追加1246/Lv6后，回将领页把对应Skills改为1246即可查看新级名字、等级和效果。只追加等级不会自动改变将领的初始Skills。简体/英语预览不能代替繁体文本修改，三份语言不会自动同步。

### 10.2 兵种特性说明

项目内“兵种编辑” → 选择兵种，在 `Feature` / `FeatureLevel` 下查看说明。

- Feature表示特性Type，不等于ArmyFeatureSettings.Id；有FeatureLevel时按相同下标的Type+Level定位记录。
- 显示本地化名称、等级、完整介绍、实际效果/第二效果/触发率/CD/范围/回合；按钮打开ArmyFeatureSettings并选中对应Id。
- 名称取 `feat_name_<Type>`；介绍优先 `feat_desc_<Type>_Lv<Level>`，缺失才使用通用 `feat_desc_<Type>`。
- 常见 `{0}`、`{1}`、`{2}` 分别是ActivatesChance、FeatureEffect、SecondEffect；未知占位符保留并警告。
- 基础兵种原本FeatureLevel为空时，只展示项目该Type最低等级的参考说明，标明实际可能受科技/运行状态影响；不会自动补FeatureLevel或把实际等级断言为1。
- 数组数量不一致、缺对应等级、多条同Type/Level或缺语言文本均显示提示。原豹2四条记录的4/5数组差异继续保留，不自动删字段让校验通过。

实际Type1的Lv1/Lv2效果为60/75；Type13的Lv1介绍代入触发率50；Type47/Lv3使用等级专属文本与两个效果参数。说明区域是数据核对入口，尚未实现完整兵种游戏UI或战斗模拟。

### 10.3 输入、刷新与外部修改

Skills/Feature等列表含非法数字时保留输入并阻止切记录/保存；兵种的本次数值和列表全部校验后才应用，不部分写入有效字段。通用JSON保存只刷新相关干净解析器，其他专用表与字符串草稿保留；同表已有草稿时，保存前版本检查报告冲突，明确重载后再编辑需要保留的部分。

返回首页不强制重新扫描；显式资源刷新仍更新文件列表与图片缓存。搜索可输入 `coastmask_hd.pkm` 等带扩展名的完整名称。首次项目索引在后台运行并可取消，取消未完成的新索引保留当前会话。

### 10.4 发布配置与可选OCR

Windows Release自包含包及日志见修复矩阵。AI密钥读取本机 `WC4_EDITOR_AI_API_KEY` 环境变量；setting模板中的AIApiKey保持空，非空会阻止构建/发布且不输出值。历史跟踪过的实际值需在服务端撤销/更换，清空当前文件不能清除历史。

OCR生成建筑需额外的 `Lib/ocr_map.exe` 和 `Lib/gen_buildings_zme.exe`。当前源码/包未提供二进制，界面已声明为可选扩展并显示安装位置；不能把构建成功当作离线OCR可用。4,580个来源文件保持不变；WindowsWPF和Android需按矩阵实际复测。
