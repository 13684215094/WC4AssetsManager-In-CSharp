# 增量项目：只保存新增和修改的文件

更新日期：2026-10-11。适用于《世界征服者 4》1.30.0，以及编辑器能够识别资源根的其他项目。游戏目录资料见 [项目说明](README.md)，本节点验证与 R01–R13 状态见 [增量项目审计](../../audits/2026-10-11-incremental-project.md)。

> 后续入口调整：桌面首页现在先填写来源与可选输出，加载后才显示编辑功能。完整交互、默认 `-edited` 目录及数据来源见 [项目优先工作流](project-workflow.md)。保存规则仍以本页为准。

## 1. 当前保存规则

新建游戏项目采用增量输出。原项目作为读取来源，另一目录保存修改；创建时不复制原项目资源。编辑器按每个文件的相对路径组合原目录与输出目录，而不是在发现输出中的 `image/`、`json/` 等目录后停止读取原目录。

| 操作 | 读取或保存行为 |
|---|---|
| 创建项目 | 校验来源和输出，生成 `.wc4-project.json` 与空资源根；不复制未修改文件或原目录的其他空目录 |
| 浏览、加载资源 | 同一路径有输出文件时读输出，否则读原项目；索引同时包含两边的文件，同路径只显示一次 |
| 无修改直接保存 | 内容与原资源一致时不生成资源文件 |
| 修改并保存 | 在输出中写入该文件的完整内容，保留原相对路径 |
| 新增资源 | 在输出中生成新文件和需要的父目录，不回写原项目 |
| 修改后又恢复原内容并保存 | 删除该文件的输出覆盖项，重新读取原文件；不影响其他修改或新增文件 |
| 继续编辑 | 打开先前的输出根，读取项目描述，再组合原资源和已保存结果 |
| 暂存地图场景 | 使用编辑器的 `Cache/Scenes`，保留未保存数据；缓存不属于项目输出，也不代表已保存 |

“增量”按文件判定：修改一个 JSON 字段会输出整张 JSON，修改一块图集可能输出整张图集及其 XML；不生成二进制差分或逐字段补丁。

## 2. 1.30.0 的具体例子

选择来源 `/home/j60100428/game/wc4/World Conqueror 4_1.30.0`，输出选择另一个新建或空目录，例如 `/home/j60100428/game/wc4/World Conqueror 4_1.30.0-edited`。来源与输出不能相同或互相包含。

刚创建时只有项目描述文件和空的 `assets/`：

```text
World Conqueror 4_1.30.0-edited/
  .wc4-project.json
  assets/
```

假设修改了 `world.bin`、一张原有 BTL 和技能表，并新增一张 BTL，保存后可能是：

```text
World Conqueror 4_1.30.0-edited/
  .wc4-project.json
  assets/
    world.bin
    stage/
      stage10001.btl
      custom/new-map.btl
    json/
      SkillSettings.json
```

其他地图、图片、语言、Android Manifest、DEX、原生库仍只存在于原项目。输出目录没有这些文件，不影响编辑器通过项目入口加载它们。若把 `SkillSettings.json` 的全部内容改回原值再保存，输出中的该文件会移除；空的父目录可能保留。

直接选择 `assets` 为来源时，输出根本身就是资源根，资源文件不会再多套一层 `assets/`。也支持来源中的 `WC4DATA/assets` 和 `Resource/WC4DATA/assets`，对应路径保持一致。

## 3. 桌面操作

1. 在首页填写原项目来源目录（必填），或点击“选择来源”。
2. 输出可自己指定或使用默认同级 `<项目名>-edited`。点击“加载项目”，程序验证路径；新的/空的目录创建增量项目，同来源的已有输出直接继续编辑。
3. 在加载后的项目概览进入地图、将领、国家等编辑器，或在资源管理器打开其他资源，修改后保存。所有项目保存路径必须位于输出目录内。
4. 普通 JSON、XML、INI、`.strings`、`.fsh`、`.vsh` 可进入内置文本编辑页。打开本身不生成输出；有实际修改再保存。此页要求 UTF-8，不验证任意文件的游戏业务语义。
5. 再次使用时填写同一来源与输出，或点击“选择已有输出”从描述中填入路径，然后加载。资源管理器已不提供直接切换另一素材目录的入口；切换项目统一回到加载表单。

关闭窗口、离开编辑器和切换项目会检查未保存状态，提供保存、放弃或取消。选择全部保存时逐文档执行；某一文档失败会停止退出或切换，先前已成功保存的文档不会整体回滚。

单个地图文档的撤销/重做跟随地图场景。普通切换在预算内保留历史；非活动场景及历史合计使用 256 MiB 的估算预算，超出后按最近使用顺序缓存地图、回收旧历史。场景标签提示历史回收，地图的未保存修改仍保留。活动地图不计入这项非活动场景预算；这不是整个进程的内存上限，历史也不会在重启后恢复。

## 4. 内容比较与冲突

| 资源 | 无修改输出的判定及限制 |
|---|---|
| BTL、world 与其他二进制 | 比较完整字节；格式往返保留已有未知区段、padding 和保留字节 |
| JSON | 比较解析后的内容，忽略缩进、BOM 和对象属性排列；数组顺序与实际值变化仍是修改。注释和排版不作为独立输出理由 |
| XML | 比较解析内容，忽略声明、普通排版和属性排列；节点、值或属性变化仍是修改；不承诺任意 XML 数值文本都被归一化 |
| 普通图片与图集 | 相同像素且原编码符合扩展名时复用原编码字节，避免未修改 WebP/JPEG 重编码产生输出；真正修改后按目标扩展编码 |
| 专用字符串表 | 没有待保存键时不输出；修改保留原 BOM、行尾和键值周围空白，恢复原值可以移除覆盖文件；删除后再新增不承诺恢复原行位置 |
| 内置文本页 | 保留 UTF-8 BOM；仅 CRLF/LF 变化不标为未保存。其他文本变化通常按字节处理，JSON/XML 另有内容比较规则 |
| 布局编辑页 | 同一加载路径且没有布局变化时跳过输出；另存到新路径是显式新增。任意布局节点的完整保真仍待验证 |

专用 JSON、头像/兵种位置 XML、布局和文本保存前检查加载时的文件版本。资源被外部程序修改后，旧文档保存会报错，保留内存修改；重新加载并重新应用需要保留的修改后再保存。该检查针对读取到的实际资源，也能发现输出覆盖文件或来源文件变化。

字符串表允许不同键在再次准备保存时合并最新内容；同一个键被外部改成不同值时拒绝覆盖。若已准备的候选内容之后又遇到磁盘修改，也会拒绝发布，需要重新准备保存。

国家删除、头像多尺寸输出、国旗战术/HD 两组图集使用批量候选保存：全部准备和暂存成功才替换；常规 I/O 失败尝试恢复已有文件，失败保留未保存状态。此流程不是断电级多文件事务；若恢复也失败，会报告错误并保留 `.tmp.bak`，需要按错误信息检查文件。

## 5. 项目描述和旧项目兼容

新项目描述示例：

```json
{
  "Version": 2,
  "SourceRoot": "/home/j60100428/game/wc4/World Conqueror 4_1.30.0",
  "AssetsRelativePath": "assets"
}
```

| 格式 | 当前行为 |
|---|---|
| `Version: 2` | 增量读取与保存；继续打开要求原资源目录存在；保存结果以当前来源为比较基准 |
| `Version: 1` | 保留旧完整副本行为，可在原目录不存在时打开；不自动清理或转换旧副本 |

上表的 v1 离线打开能力保留在 Core/CLI。当前桌面首页按来源必填且目录存在的约定加载；没有来源的旧副本需先准备有效来源路径，再使用对应工作流，不把“选择已有输出”当作绕过来源的入口。

需要从旧副本开始一个稀疏项目时，应另外创建 v2 项目，再将希望保留的修改纳入新输出。当前没有自动迁移或识别旧副本中真正修改文件的入口，不应只改 manifest 版本或批量删除旧副本文件。

v2 描述记录来源绝对路径，不保存完整资源快照或来源全量指纹。移动项目、删除原目录或换电脑后，应保证描述中的原资源路径有效；换游戏版本应新建独立项目。原资源最好保持固定，已打开文档的冲突检测不等于整个来源被锁定。

项目创建、继续打开、读取和保存拒绝目录/文件链接与越界路径。首次创建拒绝非空输出；同来源的已有输出走继续打开流程，其他来源的输出拒绝加载。创建过程取消或失败不发布部分项目；创建完成后若后续激活失败，已建立的描述可以留待重试。

## 6. 输出用于发布时的边界

稀疏输出不是完整游戏工程，不能直接当作完整解包目录打包。需要发布时，在独立的完整工作目录中准备相同版本资源，再按相对路径覆盖或添加增量输出文件；排除 `.wc4-project.json`。不要把覆盖操作指向作为编辑来源的原目录。

编辑器目前不执行上述完整目录合成、APK 打包、签名或安装，也没有删除原资源的标记机制。删除输出覆盖项只表示回退到原资源，不能代表发布时删除原文件。

引用 world 的 BTL 仍只能在自身文件中保存对象、省区和归属；不能在该 BTL 场景修改外部地形、capture、底图编号或尺寸。需要地形变化时单独保存 `world.bin`，重新打开 BTL 查看。PKM/ETC、完整对象美术、海岸和 P3 联动范围见最新审计，不因增量输出而自动完成。

## 7. CLI 与验证

```bash
dotnet run --project WC4MapEditor.Cli -- project create \
  "/home/j60100428/game/wc4/World Conqueror 4_1.30.0" \
  "/home/j60100428/game/wc4/World Conqueror 4_1.30.0-edited"

dotnet run --project WC4MapEditor.Cli -- project info \
  "/home/j60100428/game/wc4/World Conqueror 4_1.30.0-edited"
```

`project create/info` 建立本次 CLI 调用的项目读取上下文并显示合并后的资源计数，成功退出 0、调用或读取失败退出 2。其他独立 CLI 命令不会继承前一次进程的项目注册；对于输出中尚不存在的输入，需明确使用原资源路径，并将编辑结果输出到独立目录。

本节点真实项目回归：来源 4,580 个文件未复制；1,383 张 BTL 及主要专用配置无修改保存后，输出文件只有 manifest；实际修改一张本地地形 BTL 与 world 后，输出共三个文件。原目录所有文件 SHA-256 保持不变。测试说明与复现命令见 [2026-10-11 审计](../../audits/2026-10-11-incremental-project.md)。
