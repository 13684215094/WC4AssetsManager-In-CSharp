# 1.30.0：APK 加载、科技 UI 预览与技能等级扩展

更新日期：2026-10-11。本节点追加到 [项目优先工作流](project-workflow.md) 和 [图片与配置编辑](resource-editing.md)之后。来源缺少半身像属于游戏原本状态，不要求生成或补全。

## 1. 直接加载 APK

首页“游戏项目来源”支持两种输入：包含 assets 的解包目录，或 `.apk` 安装包。可以粘贴路径，也可以点击“选择目录”或“选择 APK 安装包”。例如：

```text
来源：/home/j60100428/game/wc4/World Conqueror 4_1.30.0.apk
默认输出：/home/j60100428/game/wc4/World Conqueror 4_1.30.0-edited
```

Windows 请填写本机实际路径。输出可自行指定；解包目录和同名 APK 的默认输出相同，但两个来源不能共用一个已有输出项目，切换来源时需选择另一输出目录。

APK 读取使用 .NET ZIP 支持，不需要 Java 或 apktool。编辑器只提取 `assets/` 与 `lib/` 到独立资源缓存；SDK、签名、Manifest、DEX 等内容仍保留在原 APK，不参与缓存中的资源编辑。真实安装包包含末尾为点的 SDK 文件名，Windows 无法按普通路径提取，因而不能直接整包解压到编辑目录。

| 文件区域 | 用途 |
|---|---|
| 原 APK | 只读输入，保留原始字节，不覆盖、不重签名 |
| Windows `%LOCALAPPDATA%\WC4MapEditor\apk-cache\<SHA256>` | 提取资源供项目读取；完整性校验失败时重新提取 |
| Linux `$XDG_DATA_HOME/WC4MapEditor/apk-cache/<SHA256>`，默认 `~/.local/share` | .NET LocalApplicationData 对应缓存目录 |
| 用户输出目录 | 项目描述 `.wc4-project.json` 与新增/修改资源；不存完整解压副本 |

首次加载有校验和提取进度，可以取消；缓存按 APK SHA-256 复用。重新打开输出时校验原 APK 与缓存文件，缺失或损坏缓存从原 APK 重建。原 APK 的内容变化时拒绝套用旧输出，防止不同版本错配。保留原 APK 可恢复缓存；仅有增量输出不能替代来源安装包。

APK 输出使用 v3 项目描述，额外记录 `SourceApk` 和 `SourceApkSha256`；v1 完整副本与 v2 目录增量项目继续兼容。缓存里的实际来源根为 `SourceRoot`，用户选择的路径为 `SourcePath`。

路径穿越、资源链接、大小写冲突、重复文件、文件/目录冲突和 Windows 不可用资源名会被拒绝；验证失败或取消不会发布半成品输出。最大解压资源量 16 GiB，包内条目最多 200,000。

CLI 同样支持：

```bash
dotnet run --project WC4MapEditor.Cli -- project create \
  "/home/j60100428/game/wc4/World Conqueror 4_1.30.0.apk" \
  "/path/to/apk-edited"
dotnet run --project WC4MapEditor.Cli -- project info "/path/to/apk-edited"
```

**APK 加载成功不代表已经支持生成可安装 APK。** 当前保存仍是增量资源目录；重建、签名与安装沿用外部工具流程，不把缓存作为完整 apktool 工程。

## 2. 总部科技和 UI 的关系

项目概览 → “扩展配置与界面资源” → **总部科技与 UI 预览**，打开 `TechnologySettings.json`。字段面板下方显示科技树，可调整分隔条、缩放并横向滚动。

预览输入来自同一份未保存的数据。修改 `Categorys`、`Type`、`Level`、`Position`、`NeedID`、`UpgradeID`、费用与描述值后约 180 ms 更新；无效输入保留上一次有效预览并提示，修正前不导出旧图。预览不会自动保存配置。

| 数据或资源 | 预览用途 |
|---|---|
| `Categorys` | 0–7 分组，按组查看 |
| `Position=[行,列]` | 第一项控制垂直行，第二项控制横向列；以 1 为起点 |
| `UpgradeID` | 金色升级线 |
| `NeedID` | 青色前置依赖线 |
| `Type` | `tech_name_<Type>` 名称、`tech_<Type>.png` 或 `_1/_2` 图标 |
| `Level`、费用、`TechDesc/TechValue` | 节点等级和所选节点信息 |
| 当前项目 `layout.xml`、`layout_x.xml` | `form_technique/rpt_items` 的网格宽高、单项尺寸和 itemcount；可选择布局变体 |
| 当前项目图集和 `font/NotoSans_cn.otf` | 节点背景、图标和中文字体 |

真实网格宽 2300，单项宽 230，高 106，itemcount=50，即 10 列、5 行。实际有效记录占前四行。外部 Excel 字段注释曾把 Position 写成 `[横向列,纵向行]`；本预览按实际位置范围和 10 列布局使用 `[行,列]`，不要据旧注释反转两个值。

原表有 **46 个双图标格子**，都是两个不同 Type 共用位置；布局里的 `firIcon/secIcon` 正是用于这种组合，不能一律判为重复。预览显示两项，点击对应半边选择记录。同格超过两项或同 Type 重复才报重叠。还检查越界、缺失引用、升级/依赖环和描述数组数量，缺图标另行提示。

原始数据中 `Id=305062` 的 `UpgradeID=305063`，表内不存在 `305063`。该诊断保留显示，不自动修改游戏原表，不能把它算成本轮编辑引入的错误。

“编辑科技页面布局”会先处理未保存配置，再进入现有布局编辑器并选中 `form_technique`。在那里修改宽度、itemwidth、itemcount 等并保存，然后重开科技页观察结果。只改布局时注意两份布局的设备适配；预览不会自动改另一份。

“导出预览 PNG”保存原始网格尺寸的效果图，导出目录需位于游戏来源和修改输出之外，避免把审阅图片混入游戏资源。实时图是用于编辑的布局与关系预览，不复刻原生解锁状态、点击升级逻辑、动画、游戏的精确连线形状或全部设备适配。

## 3. 兵种修改在哪里

加载项目 → “角色、国家与战斗数据”中有两个入口：

| 入口 | 真实 1.30.0 表 | 可改内容 |
|---|---|---|
| **兵种编辑** | ArmySettings，736 条 | 攻击、HP、防御、机动、射程、造价、编队、特性、动画名、XML 位置和本地化；已有编队/等级数值模拟 |
| **精英兵种、特性与等级** | EliteArmySettings，552 条 | 精英等级、对应 ArmyId、解锁、资源/物品费用等 |
| 同一扩展入口 | ArmyFeatureSettings，461 条 | 特性效果、等级、条件、CD、范围、状态及关联兵种 |
| 同一扩展入口 | ArmyLevelSettings，7 条 | 普通军队等级增益和经验需求 |
| 同一扩展入口 | ArmySubTypeSettings、ArmyNumberSettings | 其他兵种子类型/数量表，有资源时列出 |

普通兵种专用页仍需 `config/def_armypos.xml`，缺文件时可从“全部配置表”直接修改 ArmySettings。新增 Army/Anim 或新特性 Type 不会自动生成动画、美术与原生执行逻辑；已有数据关系检查可辅助核对引用，仍需要游戏实测。

## 4. 钢铁洪流从五级扩成六级

项目概览 → “角色、国家与战斗数据” → **技能与等级链**，搜索“钢铁洪流”或 `1245`。

真实 1.30.0：

```text
Type=24
Lv1 1241 → Lv2 1242 → Lv3 1243 → Lv4 1244 → Lv5 1245 → 0
```

1. 选择 Lv5、Id=1245，点击 **追加下一级**。
2. 工具深拷贝末级，保留 Type、Series、图标和未知字段，生成 Lv6 并把 `1245.UpgradeId` 接到它。
3. 原表 1246 未占用，所以新增 Id=1246、Level=6、UpgradeId=0；遇到 Id 已占用时分配当前表最大 Id+1。
4. 新级默认沿用 Lv5 的效果 25、费用 400 和评分等，**不会猜测新级平衡公式**。自行修改，例如把 SkillEffect 设为 30，并按需要调整 CostMedal/Score。
5. 等级链、图标、效果与费用在当前页面实时展示。保存后输出只有变化的 SkillSettings；文本未改时不写 stringtable。
6. 若希望某位将领初始拥有 Lv6，再到将领编辑的 `Skills` 数组，把该技能对应 Id 改成新 Id。进修阶段的 Skills 在进修表内另行调整。

只能对最高等级、UpgradeId 为 0 的链尾追加；同 Type 等级重复、所选 Id 重复或非链尾会拒绝。原“新增”用于独立新记录，不是自动续接现有技能链。

`Level=6` 是一个技能的第六级，**与将领第六个技能槽不同**。现有 BTL 的五槽结构可以存每槽的 6 级数值，自动检查要求记录存在并且等级能放入字节；本功能不修改 SO 或扩展 BTL 技能槽。

工具验证新增行与升级链能保存、重开；游戏是否允许升级到 Lv6、效果分派、按钮/等级显示与旧存档持久化仍需 Android 验收。新 Type 也不能仅通过 JSON 自动得到引擎效果。
